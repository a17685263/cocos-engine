# Windows crisp small labels and native outlines

This branch targets Cocos Creator 3.8.1 Windows Native builds. It replaces the
system-font GDI label path with DirectWrite GDI-compatible measuring and
hinting, and implements the previously empty Win32 `strokeText()` path.

## What changes

- Installed Windows fonts, including SimSun, are measured and
  rasterized with DirectWrite `DWRITE_RENDERING_MODE_GDI_CLASSIC`.
- Text origins are snapped to physical pixels before rasterization.
- ClearType's three coverage channels are converted to a tint-safe grayscale
  mask. This avoids color fringes when Cocos applies arbitrary label colors.
- Native label outlines are generated by dilating the glyph coverage mask and
  compositing it with `strokeStyle`. The fill is then alpha-composited over the
  outline.
- Project TTF files registered through `AddFontResource` keep the original GDI
  path as a compatibility fallback.

## Use with Creator 3.8.1

1. Keep this checkout on `fix/win32-crisp-label-outline`.
2. Initialize `native/external` as described by the Cocos engine customization
   guide. The matching external tag is recorded in `native/external-config.json`.
3. In Creator, open **Preferences > Engine Manager**.
4. Disable the built-in TypeScript and native engines and select this engine
   checkout for both paths.
5. Restart Creator, compile the engine, and rebuild the Windows project with
   the link template.
6. Clear the Creator engine/build cache before comparing an older executable.

Do not point Creator 3.8.1 at a different engine tag. Upgrade the editor and
engine source together if the project later moves to another 3.8 patch release.

## Recommended label settings for 13-14 px SimSun

- Use the Windows system family name `SimSun` (or its localized family name).
- Keep the label and its parent hierarchy at scale 1 whenever possible.
- Prefer a fixed font size over `SHRINK` for desktop UI.
- Start with `Cache Mode = NONE`, then verify `CHAR` separately.
- Use an outline width of 1 physical pixel for 13-14 px text. A 2 px outline
  can consume too much of the inner glyph at this size.
- Keep final label positions on integer screen pixels.

## Regression matrix

Test these cases in both editor preview and a Windows Native executable:

| Case | Values |
| --- | --- |
| Font size | 13, 14, 16, 24 |
| Cache mode | NONE, BITMAP, CHAR |
| Outline | disabled, 1 px, 2 px |
| Text | Chinese, Latin, digits, mixed text, trailing spaces |
| Window DPI | 100%, 125%, 150%, 200% |
| Window mode | windowed, resized, fullscreen |
| Style | normal, bold, italic, translucent colors |

Compare screenshots at their original pixel size. Image viewers must be at
100% zoom; otherwise their own filtering can obscure the result.

## Known scope

This implementation intentionally fixes Windows Native. Web and Electron
builds still use Chromium's Canvas text rasterizer and are not affected. Full
DirectWrite support for project-private TTF collections would require a custom
DirectWrite font loader; those fonts currently use the compatible GDI fallback.
